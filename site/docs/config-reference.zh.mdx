该文档主要来自 Ghostty 的 [Option Reference](https://ghostty.org/docs/config/reference)。

这里列出了 Gui 全部配置项的参考。这些选项大致按照使用频率排序，
并与相关选项分组。建议使用浏览器的搜索功能来查找你需要的选项。

## Gui 独有的键

## `tab-position`

标签栏的位置 —— 顶部、左侧或右侧。

## `compact`

true（默认）时窗格紧贴排列，分隔线为 1 DIP；false 时窗格浮动显示为圆角卡片。

## `sidebar-width-left`

左侧标签栏的宽度，单位为 DIP；拖动其边缘时，应用会把新宽度写回配置。

## `sidebar-width-right`

右侧标签栏的宽度，单位为 DIP；拖动其边缘时，应用会把新宽度写回配置。

## `debug-tap`

以十六进制把两个方向上原始的 VT 字节流记录到日志中。

## `crash-dumps`

向 Windows 错误报告注册以获取完整转储，崩溃后转储文件会留在 %TEMP%\gui-dumps 中。

## `language`

Gui 图形界面的语言：`en` 或 `zh-CN`。例如：

```
language = zh-CN
```

空值（默认）会跟随系统语言：简体中文系统使用中文字符串，其他语言系统使用英文。

与 Ghostty 不同，该值可以在运行时重新加载，无需重启。

这只改变 Gui 自身的界面文字，不会改变在终端*内部*运行的程序所使用的语言，
后者仍遵循系统默认值。

## `font-family`

## `font-family-bold`

## `font-family-italic`

## `font-family-bold-italic`

要使用的字体族。

你可以用 CLI 生成有效值列表：

```
gui +list-fonts
```

在 Gui 自己的终端里运行该命令会打开字体浏览器：左侧列出已安装的字体族，右侧用该字体的真实字形预览；按 Enter 会把选中的字体写入配置的 `font-family`。输出被重定向或不在 Gui 终端里运行时，则改为每行打印一个字体族及其可用样式。

该配置可以重复多次，用于在主字体中缺少所需码位时指定首选的
回退字体。这对多语言、符号字体等场景尤其有用。

关于 emoji：Gui 用 DirectWrite 绘制文字并开启彩色字形
（`EnableColorFont`），所以 emoji 会以彩色字形渲染。默认的
JetBrainsMono Nerd Font 不含 emoji 字形，主字体没有覆盖的字符会交给
DirectWrite 的系统回退，在 Windows 上通常由 Segoe UI Emoji 补上。
你也可以在这里追加字体族作为回退，或用 `font-codepoint-map`
把指定码位固定映射到某个字体。

具体样式（粗体、斜体、粗斜体）不需要显式设置。如果某个样式没有设置，
就会在常规样式（font-family）中寻找风格变体。如果找不到风格变体，
Gui 会使用常规样式。这样可以避免仅仅为了获得粗体之类的样式
而回退到其他字体族。这一点同样适用于你为某个样式显式指定字体族的情况。
例如，如果你设置 `font-family-bold = FooBar` 而找不到 "FooBar"，
Gui 会为粗体样式使用 `font-family` 中设置的字体。

最后，某些样式在不受支持时可能会被合成。例如，如果某个字体没有斜体
样式，也没有指定替代的斜体字体，Gui 会对常规样式施加倾斜来合成
斜体。如果你想禁用这些合成样式，可以使用下面记录的 `font-style`
配置。

你可以通过 `font-style` 系列配置完全禁用样式。更多信息请参阅
`font-style` 的文档。

如果你想覆盖之前设置的值而不是追加回退字体，可以把值指定为 `""`
（空字符串）以重置列表，然后再设置新值。例如：

```
font-family = ""
font-family = "My Favorite Font"
```

把其中任何一项作为 CLI 参数设置，都会自动清除配置文件中设置的值，
因此你不需要在设置新值之前指定 `--font-family=""`。只有在你想清除
配置文件中先前设置的值时，才需要在配置文件中这样做；或者想在 CLI 上
清除 CLI 上设置的值时才需要这样做。

## `font-style`

## `font-style-bold`

## `font-style-italic`

## `font-style-bold-italic`

为每个所需的终端字体样式使用的具名字体样式。它会根据字体自身
公布的字体样式字符串来查找样式。例如，"Iosevka Heavy" 的样式为
"Heavy"。

你也可以用这些字段完全禁用某个字体样式。如果你把下面配置的值设为
字面量 `false`，该字体样式就会被禁用。如果终端中运行的程序请求了
已被禁用的字体样式，则会改用常规字体样式。

这些配置只有在对应的 font-family 也指定时才有效。如果没有指定
font-family，那么 font-style 会被忽略，除非你是在禁用该字体样式。

## `font-synthetic-style`

控制当指定的 font-family 中没有请求的样式时，Gui 是否应合成该样式。

如果字体没有特定样式，Gui 可以合成粗体、斜体和粗斜体样式。
对于粗体，是通过在字形周围绘制粗细可变的外轮廓来实现的。对于斜体，
是通过对字形施加倾斜来实现的。对于粗斜体，则会同时应用这两种处理。

合成样式并不完美，通常看起来不如原生具备该样式的字体。不过，当字体
没有该样式时，它们有助于提供带样式的文本。

把此项设为 "false" 或 "true" 可以完全禁用或启用合成样式。你可以使用
"no-bold"、"no-italic" 和 "no-bold-italic" 禁用特定样式。用逗号分隔
即可禁用多个样式，例如 "no-bold,no-italic"。

可用的样式键有：`bold`、`italic`、`bold-italic`。

如果合成样式被禁用，那么在请求的样式不可用时就会改用常规样式。如果
字体本身具有请求的样式，则会直接使用该字体，因为该样式不是合成的。

<Warning>
 一个常见的错误是禁用了 `bold` 或 `italic`，却没有禁用
`bold-italic`。只禁用 `bold` 或 `italic` 并不会禁用 `bold-italic`
样式中的相应部分。如果你想禁用 `bold-italic`，必须显式禁用它。
你无法部分禁用 `bold-italic`。
</Warning>

默认情况下，合成样式处于启用状态。

## `font-feature`

应用字体特性。要启用多个字体特性，可以重复设置多次，或使用
逗号分隔的特性设置列表。

特性设置的语法如下，其中 `feat` 是一个特性：

  * 启用特性，例如 `feat`、`+feat`、`feat on`、`feat=1`。
  * 禁用特性，例如 `-feat`、`feat off`、`feat=0`。
  * 设置特性值，例如 `feat=2`、`feat = 3`、`feat 4`。
  * 特性名称可以用引号包裹，这意味着此配置在语法上应兼容
    `font-feature-settings` CSS 属性。

语法相当宽松，但无效的设置会被静默忽略。

该字体特性会应用于 Gui 渲染的所有字体。未来的增强将允许
针对特定字面（face）。

要禁用编程连字，请使用 `-calt`，因为这是编程连字的典型特性名。
要了解你的字体有哪些字体特性以及它们的作用，请使用字体检查工具，
例如 [fontdrop.info](https://fontdrop.info)。

要大体上禁用大多数连字，请使用 `-calt, -liga, -dlig`。

## `font-size`

字体大小，以磅（point）为单位。该值可以是非整数，最终会选择最接近的
整数像素大小。如果你的高 DPI 显示器上 1pt = 2px，那么指定半个磅值
就能得到奇数像素大小。

例如，13.5pt @ 2px/pt = 27px

在运行时更改此配置只会影响那些没有以任何方式手动调整过字体大小的
现有终端（例如放大或缩小过字体）。手动调整过字体大小的终端会保留
其手动调整后的大小。除此之外，现有终端的字体大小会在重新加载时更新。

## `font-variation`

## `font-variation-bold`

## `font-variation-italic`

## `font-variation-bold-italic`

一个可重复的配置，用于为可变字体设置一个或多个字体变体值。
可变字体是单个字体，其文件名通常以 `-VF.ttf` 或 `-VF.otf` 结尾，
包含一个或多个可配置轴，用于控制字重、倾斜等。并非所有字体都支持
变体；只有明确声明自己是可变字体的字体才能生效。

其格式为 `id=value`，其中 `id` 是轴标识符。轴标识符始终是 4 个字符
的字符串，例如 `wght`。要获取支持的轴列表，请查看字体文档或使用
字体检查工具。

无效的 id 和值通常会被忽略。例如，如果某个字体只支持 100 到 700
的字重，设置 `wght=800` 不会产生任何效果（不会被钳制到 700）。
你必须查阅字体文档来了解支持哪些值。

常见的轴有：`wght`（字重）、`slnt`（倾斜）、`ital`（斜体）、`opsz`
（光学尺寸）、`wdth`（宽度）、`GRAD`（渐变）等。

## `font-codepoint-map`

强制一个或一段 Unicode 码位映射到指定的具名字体。如果你想支持
特殊符号，或者想使用在你的特定字体下渲染效果更好的特定字形，
这会很有用。

语法为 `codepoint=fontname`，其中 `codepoint` 可以是单个码位或一个
范围。码位必须用完整的 Unicode 十六进制值指定，例如 `U+ABCD`。
码位范围的写法为 `U+ABCD-U+DEFG`。你可以为同一字体指定多个范围，
用逗号分隔，例如 `U+ABCD-U+DEFG,U+1234-U+5678=fontname`。字体名称
与你在 `font-family` 中使用的值相同。

此配置可以重复多次，以指定多个码位映射。

在运行时更改此配置只会影响新建的终端，即新窗口、标签页等。

## `clipboard-codepoint-map`

在把文本复制到剪贴板时，将特定的 Unicode 码位映射为替换值。

此配置允许你在把终端内容复制到剪贴板时，用其他字符或字符串替换
特定的 Unicode 字符。这对于把特殊的终端符号转换为更兼容的字符，
以便粘贴到其他应用中很有用。

语法与 `font-codepoint-map` 类似：
- 单个码位：`U+1234=U+ABCD` 或 `U+1234=replacement_text`
- 码位范围：`U+1234-U+5678=U+ABCD`

示例：
- `clipboard-codepoint-map = U+2500=U+002D`（制表符横线 → 连字符）
- `clipboard-codepoint-map = U+2502=U+007C`（制表符竖线 → 竖线符）
- `clipboard-codepoint-map = U+03A3=SUM`（希腊字母 sigma → "SUM"）

此配置可以重复多次以指定多个映射。对于重叠的范围，后面的条目
优先于前面的条目。

<Note>
 这只适用于文本复制操作，不适用于 URL 复制。
</Note>

## `font-shaping-break`

把字体塑形拆分成多个 run 的位置。

"run" 是被一起塑形的一段连续文本。"塑形"（shaping）是把文本（码位）
转换为字形（可渲染字符）的过程。连字就是这样形成的。例如，如果某个
编程字体把 "!=" 变成单个字形，那么它必须在同一个 run 中看到相邻的
"!" 和 "="。当 run 被断开时，文本会被分别塑形。继续上面的例子，如果
"!" 位于一个 run 的末尾，而 "=" 位于下一个 run 的开头，那么连字就
不会形成。

Gui 会在某些位置断开 run，以提高可读性或可用性。例如，Gui
默认会在光标下方断开 run，这样文本编辑时就能看到单个字符而不是连字。
此配置让你可以控制这一行为。

用逗号组合多个值以设置多个选项。给选项加上 "no-" 前缀即可禁用它。
启用和禁用选项可以同时进行。

可用选项：

  * `cursor` - 在光标下方断开 run。

## `adjust-cell-width`

## `adjust-cell-height`

所有这些配置的行为都是调整由字体决定的各种度量值。取值可以是
整数（1、-1 等）或百分比（20%、-15% 等）。无论哪种形式，该值都
表示在原值基础上改变的量。

例如，取值 `1` 会把该值增加 1，而不是把它字面设置为 1。取值 `20%`
会把该值增加 20%，依此类推。

这些值几乎没有校验，因此错误的值（例如 `-100%`）可能让终端无法使用。
请谨慎且合理地使用。

部分取值会被钳制到最小值或最大值。这会让某些值看起来被忽略了。
例如，许多 `*-thickness` 调整不能低于 1px。

`adjust-cell-height` 还有一些额外的行为需要说明：

  * 字体将在单元格中垂直居中。

  * 光标会保持与字体相同的大小，但可以通过 `adjust-cursor-height`
    单独调整。

  * Powerline 字形会随单元格高度一起调整，从而让状态栏之类的
    内容继续保持对齐。

## `adjust-font-baseline`

从单元格底部到文本基线的距离调整，单位为像素或百分比。
增大该值会把基线向上移动，减小则向下移动。
关于调整的说明请参阅 `adjust-cell-width`。

## `adjust-underline-position`

从单元格顶部到下划线上边缘的距离调整，单位为像素或百分比。
增大该值会把下划线向下移动，减小则向上移动。
关于调整的说明请参阅 `adjust-cell-width`。

## `adjust-underline-thickness`

下划线的粗细，单位为像素。
关于调整的说明请参阅 `adjust-cell-width`。

## `adjust-strikethrough-position`

从单元格顶部到删除线上边缘的距离调整，单位为像素或百分比。
增大该值会把删除线向下移动，减小则向上移动。
关于调整的说明请参阅 `adjust-cell-width`。

## `adjust-strikethrough-thickness`

删除线的粗细调整，单位为像素或百分比。
关于调整的说明请参阅 `adjust-cell-width`。

## `adjust-overline-position`

从单元格顶部到上划线上边缘的距离调整，单位为像素或百分比。
增大该值会把上划线向下移动，减小则向上移动。
关于调整的说明请参阅 `adjust-cell-width`。

## `adjust-overline-thickness`

上划线的粗细调整，单位为像素或百分比。
关于调整的说明请参阅 `adjust-cell-width`。

## `adjust-cursor-thickness`

条形光标和描边矩形光标的粗细调整，单位为像素或百分比。
关于调整的说明请参阅 `adjust-cell-width`。

## `adjust-cursor-height`

光标的高度调整，单位为像素或百分比。目前适用于所有光标类型：
bar、rect 和 outlined rect。
关于调整的说明请参阅 `adjust-cell-width`。

## `adjust-box-thickness`

制表符字符的粗细调整，单位为像素或百分比。
关于调整的说明请参阅 `adjust-cell-width`。

## `adjust-icon-height`

nerd font 图标最大高度的调整，单位为像素或百分比。

正值（负值）会增大（减小）图标的最大高度。这未必会同等影响所有
图标：效果取决于图标的默认大小是否受高度约束，而这又取决于图标
和主字体两者的宽高比。

某些为制表符绘制和终端图形设计的图标（例如 Powerline 符号）
不受此选项影响。

关于调整的说明请参阅 `adjust-cell-width`。

## `theme`

要使用的主题：内置主题名称，或 `themes` 文件夹中的文件名。Gui 还支持
分别为浅色和深色模式指定不同的主题。

主题名按文件名解析：先找配置文件旁的 `themes` 文件夹
（`%APPDATA%\gui\themes`），再找可执行文件旁内置的
`Assets\Themes\light` 和 `Assets\Themes\dark`。自己文件夹里的同名主题会
覆盖内置主题。名称不能包含路径分隔符，`theme` 只接受名字而不是路径。

要查看可用主题列表，请运行 `gui +list-themes`。

主题文件只设置颜色：`background`、`foreground`、`cursor-color`、
`selection-background`、`selection-foreground` 和 `palette`。文件必须同时
设置 `background` 和 `foreground` 才会被加载，其它键会被忽略，因此主题
不能改变行为，也不能引入其他文件。请不要使用来自不受信任来源的主题文件。

通过 background、foreground、palette 等指定的任何额外颜色都会覆盖
主题中指定的颜色。

要为浅色和深色模式指定不同的主题，请使用以下语法：
`light:theme-name,dark:theme-name`。例如：
`light:Rose Pine Dawn,dark:Rose Pine`。所有值周围的空白都会被去除，
浅色和深色的顺序无关紧要。此形式中必须同时指定浅色和深色。使用哪一半
由 `window-theme` 决定。

> **Gui**
>
> 主题名称，或使用 light:X,dark:Y 为不同外观分别指定；应用自带 Ghostty 主题。实际绘制时只会使用 window-theme 所选定的那一半。

## `background`

窗口的背景色。
可用十六进制（`#RRGGBB` 或 `RRGGBB`）或具名的 X11 颜色指定。

## `foreground`

窗口的前景色。
可用十六进制（`#RRGGBB` 或 `RRGGBB`）或具名的 X11 颜色指定。

## `background-image`

终端的背景图像。

这应当是一个 PNG 或 JPEG 文件的路径，其他图像格式尚不支持。

背景图像目前是按终端而不是按窗口生效的。

它覆盖整个 pane，pane header 与内边距也算在内；网格绘制在图像上层，
因此使用默认背景色的单元格会把图像透出来。

解码后的位图由同一进程内的所有分屏共享，不会在显存中重复一份。

## `background-image-opacity`

背景图像的不透明度。

这是相对于 `background-opacity` 的值而言的。

Gui 的处理与 Ghostty 不同：取值限定在 `0.0` 到 `1.0`，大于 `1.0` 会按
`1.0` 处理。图片会以“本值 × `background-opacity`”的不透明度，叠加在面板
背景之上。

默认 `background-opacity = 1.0` 时，图片就是直接盖在背景色上。背景不透明
度较低时，图片叠在已经半透明的面板之上，因此看起来会比面板背景明显更不
透明。

Ghostty 则是先把图片与背景色合成，再整体应用 `background-opacity`，并且
允许大于 `1.0` 的取值。

## `background-image-position`

背景图像的位置。

有效值：
  * `top-left`
  * `top-center`
  * `top-right`
  * `center-left`
  * `center`
  * `center-right`
  * `bottom-left`
  * `bottom-center`
  * `bottom-right`

默认值为 `center`。

## `background-image-fit`

背景图像的适配方式。

有效值：

 * `contain`

   保持宽高比，把背景图像缩放到仍能完整容纳在终端内的最大尺寸，
   使整幅图像都可见。

 * `cover`

   保持宽高比，把背景图像缩放到能完全覆盖终端的最小尺寸。这可能导致
   图像的一条或多条边缘被终端边缘裁掉。

 * `stretch`

   把背景图像拉伸到终端的完整大小，不保持宽高比。

 * `none`

   不缩放背景图像。

默认值为 `contain`。

## `background-image-repeat`

是否重复背景图像。

如果设为 true，当背景图像未完全填满终端区域而在其周围留有空白的
情况下，就会重复该背景图像。

默认值为 `false`。

## `selection-foreground`

## `selection-background`

选区的前景色和背景色。如果没有设置，选区颜色就是反转后的窗口背景色
和前景色（注意：不要与单元格的前景/背景色混淆）。
可用十六进制（`#RRGGBB` 或 `RRGGBB`）或具名的 X11 颜色指定。

## `selection-clear-on-typing`

输入时是否清除选中的文本。默认值为 `true`。这也是大多数终端模拟器
以及文本输入框的典型行为。如果把它设为 `false`，输入时选中的文本
不会被清除。

“输入”特指任何能产生数据并发送给终端内运行的应用（例如 shell）的
非修饰键（shift、control、alt 等）按键。此外，当任何预编辑或组合
输入状态开始时（例如输入日语等语言时），选区也会被清除。

如果此项为 `false`，仍可以通过单击一次或按 `escape` 手动清除选区。

## `selection-clear-on-copy`

复制后是否清除选中的文本。默认值为 `false`。

设为 `true` 时，在调用 `copy_to_clipboard` 键盘绑定的任何复制操作
之后，选区都会被自动清除。需要注意的是，如果复制操作是通过
`copy-on-select` 触发的，则不会清除选区。

设为 `false` 时，复制后选区仍然可见，可以看清复制了什么，也可能
对同一选区执行其他操作。

## `selection-word-chars`

在文本选择操作（例如双击）中标记单词边界的字符。选择单词时，
选区会在这些字符中的任意一个处停止。

这类似于 zsh 中的 `WORDCHARS` 环境变量，区别在于这里指定的是边界
字符而不是单词字符。默认值包含在代码和普通文本中通常用于分隔单词
的常见分隔符和标点。

此字符串中的每个字符都会成为一个单词边界。支持多字节 UTF-8 字符，
但只能指定单个码位。不支持多码位序列（例如 emoji）。

空字符（U+0000）始终被视为边界，无需包含在此配置中。

默认值：`` \t'"│`|:;,()[]{}<>$ ``

要添加或移除特定字符，可以把它设为一个自定义值。例如，要把分号
视为单词的一部分：

```
selection-word-chars = " \t'\"│`|:,()[]{}<>$"
```

## `minimum-contrast`

前景色和背景色之间的最小对比度。对比度是介于 1 和 21 之间的值。
值为 1 表示允许没有对比度（例如黑底黑字）。该值是
[WCAG 2.0 规范](https://www.w3.org/TR/WCAG20/)中定义的对比度。

如果你想避免出现不可见的文本（颜色与背景相同），1.1 是一个不错的
取值。如果你想避免出现难以阅读的文本，3 或更高的值是不错的选择。
值越高，文本越有可能变成黑色或白色。

此值不适用于 Emoji 或图像。

## `palette`

许多终端应用使用的 256 色形式的调色板。此配置的语法为 `N=COLOR`，
其中 `N` 是 0 到 255（对应终端颜色表中的 256 种颜色），`COLOR` 是
常见的 RGB 颜色代码，例如 `#AABBCC` 或 `AABBCC`，也可以是具名的
X11 颜色。例如，`palette = 5=#BB78D9` 会设置“紫色”。

调色板索引可以使用十进制、二进制、八进制或十六进制。除非使用前缀，
否则默认按十进制处理：`0b` 表示二进制，`0o` 表示八进制，`0x` 表示
十六进制。

关于颜色索引的定义以及它们规范上对应的颜色，
[请参阅此速查表](https://www.ditig.com/256-colors-cheat-sheet)。

对于大多数主题，你只需要设置前 16 种颜色（0–15），因为调色板的
其余部分（16–255）默认会自动生成（详情请参阅 `palette-generate`）。

## `palette-generate`

是否从 16 种基础 ANSI 颜色自动生成扩展的 256 色调色板
（索引 16–255）。

这让主题作者只需指定 16 种基础颜色，其余调色板部分就会以一致且
美观的方式自动生成。

启用后，6×6×6 色立方和 24 级灰度渐变会从基础调色板的插值中得出，
从而获得更协调的外观。通过 `palette` 显式设置的颜色永远不会被覆盖。

默认值为 false（禁用），因为许多使用 256 色调色板的传统程序都硬编码
了关于这些颜色是什么的假设（大多假定为 xterm 256 色调色板）。不过，
对于想要自定义调色板又不想指定全部 256 种颜色的主题作者和用户来说，
这仍然是一个非常有用的工具。

关于生成方式的更多信息，请参见：
https://gist.github.com/jake-stewart/0a8ea46159a7da2c808e5be2177e1783

## `palette-harmonious`

反转启用 `palette-generate` 时生成的调色板颜色，使颜色按相反顺序
排列。这使基于调色板的应用在浅色和深色模式下都能良好工作，因为
这些调色板始终是相对较好的颜色。

此项默认关闭，因为某些传统终端应用硬编码了调色板索引 16–231
按从暗到亮排序的假设，启用此项会让它们无法阅读。这并不是一个
普遍合理的假设，我们鼓励现代终端应用以更具语义的方式使用索引。

如果 `palette-generate` 被禁用，此项没有任何效果。

更多信息请参阅 `palette-generate`。

## `cursor-color`

光标的颜色。如果没有设置，会选择一个默认值。

可以直接用十六进制（`#RRGGBB` 或 `RRGGBB`）或具名的 X11 颜色指定
颜色。

此外，还可以使用特殊值让颜色在运行时与其他颜色匹配：

  * `cell-foreground` - 匹配单元格前景色。

  * `cell-background` - 匹配单元格背景色。

## `cursor-opacity`

光标的不透明度（透明度的反面）。值为 1 表示完全不透明，值为 0
表示完全透明。小于 0 或大于 1 的值会被钳制到最接近的有效值。
注意，像 0.3 这样足够小的值可能实际上几乎不可见，并可能让你很难
找到光标。

## `cursor-style`

光标的样式。这会设置默认样式。运行中的程序仍可以通过转义序列
（例如 `CSI q`）请求显式的光标样式。shell 配置通常会请求特定的
光标样式。

注意，无论此配置如何，shell 集成都会在提示符处自动把光标设为条形。
你可以通过指定 `shell-integration-features = no-cursor` 或完全禁用
shell 集成来禁用该行为。

有效值：

  * `block`
  * `bar`
  * `underline`
  * `block_hollow`

## `cursor-style-blink`

设置光标的默认闪烁状态。这只是默认状态；运行中的程序可以使用
`DECSCUSR`（`CSI q`）覆盖光标样式。

如果没有设置此项，光标默认不闪烁。把它设为 `true` 才会闪烁。

有效值是：

  * ` `（空白）
  * `true`
  * `false`

## `cursor-text`

光标下方文本的颜色。如果没有设置，会选择一个默认值。
可用十六进制（`#RRGGBB` 或 `RRGGBB`）或具名的 X11 颜色指定。
还可以设为 `cell-foreground` 以匹配单元格前景色，
或设为 `cell-background` 以匹配单元格背景色。

## `mouse-hide-while-typing`

输入时立即隐藏鼠标。使用鼠标（按键、移动等）时，鼠标会重新可见。

## `scroll-to-bottom`

何时把表面滚动到底部。其格式是用逗号分隔的待启用选项列表。如果给
某个选项加上 `no-` 前缀，则禁用该选项。如果省略某个选项，则使用其
默认值。

可用选项：

- `keystroke` 如果设置，当用户按下会导致数据发送到 PTY 的按键时
  （基本上除修饰键或由 Gui 处理的键绑定之外的任何按键），把
  表面滚动到底部。

- `output` 如果设置，当有新数据需要显示时（例如向终端打印新行时），
  把表面滚动到底部。

默认值为 `keystroke, no-output`。

## `mouse-shift-capture`

决定运行中的程序能否检测到与鼠标点击同时按下的 shift 键。通常，
shift 键用于扩展鼠标选区。

默认值 `false` 意味着 shift 键不会随鼠标协议发送，并会扩展选区。
运行中的程序可以通过 `XTSHIFTESCAPE` 序列有条件地覆盖此值。

值 `true` 意味着 shift 键会随鼠标协议发送，但运行中的程序可以通过
`XTSHIFTESCAPE` 覆盖此行为。

值 `never` 与 `false` 相同，但运行中的程序无法通过 `XTSHIFTESCAPE`
覆盖此行为。值 `always` 与 `true` 相同，但运行中的程序无法通过
`XTSHIFTESCAPE` 覆盖此行为。

如果你希望即使程序另有请求，shift 也始终扩展鼠标选区，请把此项
设为 `never`。

有效值：

  * `true`
  * `false`
  * `always`
  * `never`

## `mouse-reporting`

启用或禁用鼠标报告。设为 `false` 时，即使终端应用请求，鼠标事件也
不会被报告给它们。这让你始终能把鼠标用于选区和其他终端 UI 交互，
而不会被应用捕获鼠标输入。

设为 `true`（默认）时，终端应用可以请求鼠标报告，并会按照其请求的
模式接收鼠标事件。

这可以在运行时使用 `toggle_mouse_reporting` 键绑定动作切换。

## `mouse-scroll-multiplier`

鼠标滚轮滚动距离的乘数。

可以使用 `precision:` 或 `discrete:` 前缀，只为特定类型的设备设置
乘数。可以用逗号分隔以同时设置两种类型的乘数，例如
`precision:0.1,discrete:3`。如果未使用前缀，乘数适用于所有滚动设备。
指定前缀的功能在 Ghostty 1.2.1 中引入。

该值会被钳制到 [0.01, 10,000]。这两个都是极端值，如果你设置任一
极端值，很可能会有糟糕的体验。

对于离散设备，默认值为 "3"；对于精确设备，默认值为 "1"。

> **Gui**
>
> 每个滚轮刻度滚动的行数（默认 3）。precision 形式可以被接受，但 Windows 的滚轮属于离散设备。

## `background-opacity`

背景的不透明度（透明度的反面）。值为 1 表示完全不透明，值为 0
表示完全透明。小于 0 或大于 1 的值会被钳制到最接近的有效值。

> **Gui**
>
> 低于 1 时，整个窗口（包括窗口边框）会被统一着色一次，而不是叠加在系统亚克力效果之上；background-blur 决定使用亚克力还是纯色着色。

## `background-opacity-cells`

对显式设置了背景色的单元格应用背景不透明度。

通常，`background-opacity` 只应用于窗口背景。如果某个单元格显式设置
了背景色（例如红色），那么该背景色将是完全不透明的。由此产生的一个
结果是，某些会重绘终端背景色的终端应用（例如 Neovim 和 Tmux）
可能不会遵循 `background-opacity`（这是有意设计的）。

把此项设为 `true` 会对所有单元格应用 `background-opacity`，无论它们
是否显式设置了背景色。

## `background-blur`

当 `background-opacity` 小于 1 时是否模糊背景。

有效值：

  * 一个非负整数，指定*模糊强度*
  * `false`，等同于模糊强度 0
  * `true`，等同于默认模糊强度 20，对于好看的模糊效果而言这是
    合理的取值。更高的模糊强度可能导致渲染异常和性能问题。

> **Gui**
>
> true 使用亚克力；在 Windows 11 上 false 会绘制未经模糊的着色（Windows 10 仍保留亚克力，与 Windows Terminal 的行为一致）。

## `unfocused-split-opacity`

未聚焦分屏的不透明度（透明度的反面）。未聚焦的分屏默认会略微淡化，
以便更容易看出哪个分屏处于聚焦状态。要禁用此功能，请把此值设为 1。

值为 1 表示完全不透明，值为 0 表示完全透明。由于“0”没有用处
（会让窗口看起来非常怪异），最小值是 0.15。这个值看起来仍然很怪异，
但至少能看清发生了什么。超出 0.15 到 1 范围的值会被钳制到最接近的
有效值。

## `unfocused-split-fill`

用于让未聚焦分屏变暗的颜色。未聚焦分屏是通过在该分屏上渲染一个
半透明矩形来变暗的。此项设置该矩形的颜色，可用于精细控制变暗效果。

默认值为背景色。

可用十六进制（`#RRGGBB` 或 `RRGGBB`）或具名的 X11 颜色指定。

## `split-divider-color`

分屏分隔线的颜色。如果没有设置，会选择一个默认值。
可用十六进制（`#RRGGBB` 或 `RRGGBB`）或具名的 X11 颜色指定。

## `command`

要运行的命令，通常是一个 shell。如果它不是绝对路径，会在 `PATH` 中
查找。如果没有设置，会从你的系统中查找一个默认值。默认查找规则是：

  * `SHELL` 环境变量

  * `passwd` 条目（用户信息）

其中可以包含运行该命令的附加参数。如果提供了附加参数，命令会使用
`/bin/sh -c` 执行，以便交给 shell 进行参数展开。

要完全避免 shell 展开，请在命令前加上 `direct:`，例如
`direct:nvim foo`。这会避免往返调用 `/bin/sh`，但也不支持任何 shell
解析，例如带空格的参数、包含 `~` 的文件路径、通配符等。

你也可以显式地在命令前加上 `shell:`，以始终把命令包裹在 shell 中。
这可用于确保在我们选择正确模式的启发式判断有误时不会使用它们。

该命令会用于所有新建的终端表面，即新窗口、标签页等。如果你只想为
Gui 启动时创建的第一个终端表面运行命令，请使用 `initial-command`
配置。

Gui 支持常见的 `-e` 标志，用于执行带参数的命令。例如
`gui -e fish --with --custom --args`。该标志会设置
`initial-command` 配置，更多信息请参阅该项。

## `initial-command`

这与 "command" 相同，但只适用于 Gui 启动时创建的第一个终端表面。
后续的终端表面会使用 `command` 配置。

在第一个终端表面创建（或关闭）之后，就无法再自动运行此初始命令。
因此，在运行时设置此项虽然有效，但只有在它是有史以来创建的
第一个终端表面时才会对其生效。

如果从命令行启动 Gui，`-e` 是设置此项的快捷方式：它后面的所有参数
都会作为命令。例如：`gui -e fish --with --custom --args`。

## `notify-on-command-finish`

控制何时发送命令完成通知。共有三个选项：

* `never` - 从不发送通知。
* `unfocused` - 仅在命令运行的表面未聚焦时发送通知（默认）。
* `always` - 始终发送通知。

命令完成通知需要启用 shell 集成，或者你的 shell 会发送 OSC 133
转义序列来标记命令的开始和结束。

## `notify-on-command-finish-action`

如果启用了命令完成通知，此项控制如何通知用户。

可用选项：

* `bell` - 默认启用
* `notify` - 默认启用

选项可以通过以逗号分隔的列表组合使用。选项可以加上 `no-` 前缀来
取反。例如 `no-bell,notify`。

## `notify-on-command-finish-after`

如果启用了命令完成通知，此项控制命令必须运行多久才会发送通知。
默认值为五秒。

时长由一系列数字后跟时间单位组成。数字和单位之间允许有空白。
每个数字和单位会相加构成总时长。

允许的时间单位如下：

  * `y` - 365 个 SI 天，即 8760 小时，或 31536000 秒。不会针对
    闰年或闰秒做调整。
  * `d` - 一个 SI 天，即 86400 秒。
  * `h` - 一小时，即 3600 秒。
  * `m` - 一分钟，即 60 秒。
  * `s` - 一秒。
  * `ms` - 一毫秒，即 0.001 秒。
  * `us` 或 `µs` - 一微秒，即 0.000001 秒。
  * `ns` - 一纳秒，即 0.000000001 秒。

示例：
  * `1h30m`
  * `45s`

单位可以重复，并会相加。这意味着 `1h1h` 等同于 `2h`。这会令人
困惑，应当避免。未来的更新可能会禁止这种写法。

最大值为 `584y 49w 23h 34m 33s 709ms 551µs 615ns`。任何大于该值的
值都会被钳制到最大值。

## `env`

传给在终端表面中启动的命令的额外环境变量。格式为
`env=KEY=VALUE`。

`env = foo=bar`
`env = bar=baz`

把 `env` 设为空字符串会把整个映射重置为默认值（空）。

`env =`

把一个键设为空字符串会从映射中移除该键及其对应的值。

`env = foo=bar`
`env = foo=`

会导致 `foo` 不会被传给所启动的命令。

多次设置同一个键会覆盖之前的条目。

`env = foo=bar`
`env = foo=baz`

会导致 `foo=baz` 被传给所启动的命令。

这些环境变量会覆盖 Gui 设置的任何现有环境变量。例如，在这里设置
`TERM_PROGRAM` 会覆盖 Gui 通常自动注入的 `Gui` 值。

这些环境变量_不会_被传给 Gui 为其他目的运行命令时所用的命令，
例如用于在浏览器中打开 URL 的 `open` 或 `xdg-open`。

## `input`

启动时作为输入发送给命令的数据。

配置的 `command` 会按通常规则启动，然后在可以提供任何其他输入之前，
此处指定的数据会被写入 pty。

字节会按原样发送，不附加任何编码。因此，对可能包含控制字符的输入
要格外小心，因为这可能被用来在 shell 中执行程序。

此值的格式为：

  * `raw:<string>` - 按原样发送原始文本。它使用 Zig 字符串字面量
    语法，因此可以指定控制字符和其他标准转义。

  * `path:<path>` - 读取文件路径并发送其内容。路径必须指向长度有限
    的文件，例如不要使用 `/dev/stdin` 或 `/dev/urandom` 之类的设备，
    因为它们会无限期阻塞终端启动。为防止过度占用内存，文件大小
    限制为 10MB。如果你有更大的文件，应编写脚本来读取该文件并
    发送到终端。

如果没有找到有效前缀，则假定为 `raw:` 输入。这是一个易用性设计，
让你可以简单地写 `input = "Hello, world!"`（常见情况），而无需给
每个值都加上 `raw:` 前缀。

此配置可以重复多次以发送更多数据。数据会直接拼接，中间没有分隔
字符（例如没有换行符）。

如果任何一个输入来源不存在，则不会发送任何输入。输入来源直到终端
启动时才会验证，因此缺失的路径不会在配置验证中显示出来。

在运行时更改此配置只会影响新建的终端。

## `wait-after-command`

如果为 true，命令退出后保持终端打开。通常，运行中的命令（例如 shell）
退出时终端窗口会关闭。如果此项为 true，终端窗口会保持打开，直到
收到任意按键。

这主要用于脚本或调试。

## `abnormal-command-exit-runtime`

运行时长低于多少毫秒时，我们认为进程退出属于异常。这用于在进程
过快退出时显示错误消息。

## `scrollbar`

控制何时显示用于滚动回滚缓冲区的滚动条。

默认值为 `system`。

有效值：

  * `system` - 遵循关于何时显示滚动条的系统设置。

  * `never` - 从不显示滚动条。你仍然可以使用鼠标、键绑定动作等
    进行滚动，但不会有显示滚动条的可见 UI 控件。

## `link-url`

启用 URL 匹配。URL 会在按住 Ctrl 悬停时匹配，并使用链接 URL 对应的
默认系统应用打开。

Gui 只匹配 URL，没有自定义链接规则。

## `link-previews`

显示匹配 URL 的链接预览。

为 true 时，会为所有匹配的 URL 显示链接预览。为 false 时，从不显示
链接预览。设为 "osc8" 时，只会为使用 OSC 8 序列创建的超链接显示
链接预览（在这种情况下，链接文本可以与链接目标不同）。

## `maximize`

是否以最大化状态启动窗口。此设置适用于新窗口，不适用于标签页、
分屏等。不过，此设置会适用于所有新窗口，而不仅是第一个窗口。

## `fullscreen`

以全屏状态启动新窗口。此设置适用于新窗口，不适用于标签页、分屏等。
不过，此设置会适用于所有新窗口，而不仅是第一个窗口。

允许的值：

  * `false` - 不以全屏启动（默认）
  * `true` - 以原生全屏启动

## `title`

Gui 为窗口使用的标题。这会强制窗口标题始终为此标题，并且
Gui 会忽略程序（例如 Neovim）可能发送的任何设置标题的转义序列。

如果你想要空白标题，请用引号把这个值设为空格。例如 `title = " "`。
这实际上会隐藏标题。之所以需要这样做，是因为把值设为空白会把标题
重置为运行中程序的默认值。

此配置可以在运行时重新加载。如果设置了它，所有窗口的标题都会更新。
如果取消设置，下一个标题变更转义序列会被遵循，但之前的更改不会
追溯性地设置。后一种情况可能需要你重启 Neovim 之类的程序才能获得
新标题。

## `working-directory`

启动命令后要切换到的目录。

此设置次于 `window-inherit-working-directory` 设置。如果同一进程中
存在先前的 Gui 终端，`window-inherit-working-directory` 会优先。
否则会使用此设置。通常，此设置只用于第一个窗口。

默认值为 `inherit`。

此值必须是绝对路径、以 `~/` 为前缀的路径（波浪号会展开为用户的主
目录），或以下特殊值之一：

  * `home` - 执行用户的主目录。

  * `inherit` - 启动进程的工作目录。

## `keybind`

键绑定。格式为 `trigger=action`。重复的触发器会覆盖之前设置的值。
动作列表见[动作参考](/docs/config/keybind/reference)。

触发器：用 `+` 分隔的按键和修饰键列表。例如：`ctrl+a`、
`ctrl+shift+b`、`up`。

如果按键是单个 Unicode 码位，触发器会匹配任何产生该码位的按键。
这些会受到键盘布局的影响。例如，`a` 会匹配 QWERTY 键盘上的 `a`
键，但在 AZERTY 键盘上会匹配 `q` 键（假设为美式物理布局）。

对于 Unicode 码位，匹配是通过把修饰键集合与未修改的码位进行比较来
完成的。未修改的码位在其他软件中有时称为“未加 shift 的字符”，但这里
会考虑所有修饰键，而不仅是 shift。例如，`ctrl+a` 会匹配 `a`，但不会
匹配 `ctrl+shift+a`（在美式键盘上即 `A`）。

此外，码位匹配不区分大小写，未修改的码位在比较前始终会进行大小写
折叠。因此，配置了 `ctrl+A` 时，按下 `ctrl+a` 也会匹配。注意，这意味
着某些按键组合会因键盘布局而变得不可能。例如，`ctrl+_` 在美式键盘上
是不可能的，因为 `_` 是 `shift+-`，而 `ctrl+shift+-` 不等于 `ctrl+_`
（因为修饰键不匹配！）。关于不可能的按键组合的更多细节，可参阅 Qt
开发者撰写的这份极好的资料：
https://doc.qt.io/qt-6/qkeysequence.html#keyboard-layout-issues

物理键码可以通过 [W3C 规范](https://www.w3.org/TR/uievents-code/)中
指定的任何键码来指定。例如，`KeyA` 会匹配美式标准键盘上的物理 `a`
键，与键盘布局无关。这些区分大小写。

出于美观考虑，w3c 键码也支持蛇形命名。例如，`key_a` 等同于 `KeyA`。
唯一的例外是功能键，例如 `F1` 写作 `f1`（没有下划线）。这是我们内部
代码使用蛇形命名带来的结果，但它是特意支持并测试过的，因此可以安全
使用。它允许全小写的绑定，我觉得这样更美观。

诸如 `insert`、`up`、`f5` 等功能键也使用前面链接的 W3C 规范中指定的
键码来指定。

物理键的匹配优先级始终高于 Unicode 码位，因此如果你同时指定 `a` 和
`KeyA`，无论它们的配置顺序如何，都会始终使用物理键。

特殊键 `catch_all` 可用于匹配任何未被其他方式绑定的按键。它可以与
修饰键组合，例如 `ctrl+catch_all` 会匹配任何与 `ctrl` 同时按下且未被
其他方式绑定的按键。查找绑定时，Gui 首先尝试匹配带修饰键的
`catch_all`。如果没有找到匹配项且事件带有修饰键，则回退到不带修饰键
的 `catch_all`。

有效的修饰键为 `shift`、`ctrl`（别名：`control`）、`alt`（别名：`opt`、
`option`）和 `super`（别名：`cmd`、`command`）。你可以使用修饰键或
别名。调试键绑定时，输出中始终会使用不带别名的修饰键。

<Note>
 键盘上的 fn 或“地球”键不支持作为修饰键。这是 Gui 所使用的
操作系统和 GUI 工具包的限制。
</Note>

关于触发器的一些附加说明：

  * 修饰键不能重复，`ctrl+ctrl+a` 无效。

  * 修饰键和按键可以任意顺序，`shift+a+ctrl` 很*怪异*，
    但有效。

  * 只允许一个按键输入，`ctrl+a+b` 无效。

你也可以用 `>` 分隔多个触发器，以要求按顺序触发一系列触发器才能
激活动作。例如，`ctrl+a>n=new_window` 只有在用户先按下 `ctrl+a`、
然后单独按下 `n` 时才会触发 `new_window` 动作。在其他软件中，这有
时被称为前导键（leader key）、按键组合（key chord）、键表（key table）
等。序列中的部分数量没有硬编码限制。

<Warning>
 如果你把序列定义为 `gui` 的 CLI 参数，可能需要对键绑定加引号，
因为在大多数 shell 中 `>` 是特殊字符。例如：
gui --keybind='ctrl+a>n=new_window'
</Warning>

触发器序列有一些特殊处理：

  * Gui 会无限期等待序列中的下一个按键。无法指定超时。要强制
    输出前缀键的唯一方法是另外分配一个专门输出该键的键绑定（例如
    `ctrl+a>ctrl+a=text:foo`），或者按下一个未绑定的键，这会把两个键
    都发送给程序。

  * 如果在序列过程中按下了未绑定的键，并且存在会 `ignore` 该输入的
    `catch_all` 绑定，则整个序列会被丢弃，什么也不发生。否则，整个
    序列会被编码并发送给运行中的程序，就像没有键绑定一样。

  * 如果序列中的前缀先前已被绑定，序列会覆盖先前的绑定。例如，如果
    `ctrl+a` 绑定到 `new_window`，而 `ctrl+a>n` 绑定到 `new_tab`，
    那么按下 `ctrl+a` 不会产生任何效果。

  * 补充上一条，如果先前绑定的序列前缀被用于一个新的非序列绑定，
    那么整个先前绑定的序列都会被解除绑定。例如，如果你绑定了
    `ctrl+a>n` 和 `ctrl+a>t`，然后直接绑定 `ctrl+a`，那么 `ctrl+a>n`
    和 `ctrl+a>t` 都会被解除绑定。

  * `global:` 或 `all:` 前缀的触发器不允许使用触发器序列。这是我们
    将来可能移除的限制。

动作是触发器满足时要执行的动作。其格式为 `action` 或 `action:param`。
后一种形式只有在动作需要参数时才有效。

  * `ignore` - 什么也不做，忽略该按键输入。这可用于把某些输入
    黑洞化，使其不产生任何效果。

  * `unbind` - 移除绑定。这会移除先前的动作，并且如果该键是可打印的，
    会被透传给子命令。unbind 会移除任何匹配的触发器，包括以
    `physical:` 为前缀的触发器，而无需指定前缀。

  * `csi:text` - 发送一个 CSI 序列。例如 `csi:A` 发送“光标上移”。

  * `esc:text` - 发送一个转义序列。例如 `esc:d` 删除到右侧单词末尾。

  * `text:text` - 发送一个字符串。使用 Zig 字符串字面量语法。
    例如 `text:\x15` 发送 Ctrl-U。

  * 所有其他动作见[动作参考](/docs/config/keybind/reference)。

关于动作的一些说明：

  * 参数在 `:` 之后按原样获取。双引号或其他机制会被包含在内，
    而不会被解析。如果你想发送包含空格的字符串值，请把整个
    触发器/动作包裹在双引号中。例如：
    `--keybind="up=csi:A B"`

还有一些可以为键绑定指定的特殊值：

  * `keybind=clear` 会清除所有已设置的键绑定。警告：这会移除截至
    目前的所有键绑定，包括默认键绑定。

键绑定触发器可以加上一些特殊前缀来改变键绑定的行为。包括：

 * `all:`

   让键绑定应用于所有终端表面。默认情况下，键绑定只应用于聚焦的
   终端表面。如果启用此项，键绑定会被发送到所有终端表面。这只适用
   于表面相关的动作。对于已经是全局的动作（例如 `quit`），此前缀
   没有效果。

 * `global:`

   让键绑定变为全局。默认情况下，键绑定只在 Gui 内且满足适当
   条件时（应用聚焦，有时需要终端聚焦等）才有效。如果你希望键绑定
   在整个系统范围内生效（例如即使 Gui 未聚焦时也生效），请指定
   此前缀。此前缀隐含 `all:`。

   注意：这并非在所有环境中都有效；更多信息请参阅下面的附加说明。

 * `unconsumed:`

   不消费输入。默认情况下，键绑定会消费输入，意味着相关的编码
   （如果有）不会被发送给终端中运行的程序。如果你希望把编码值发送
   给程序，请在整个键绑定之前指定 `unconsumed:` 前缀。例如：
   `unconsumed:ctrl+a=reload_config`。无论此设置如何，以 `global:` 和
   `all:` 为前缀的键绑定始终会消费输入。由于它们不与特定终端表面
   关联，因此永远不会被编码。

 * `performable:`

   仅在动作能够执行时才消费输入。例如，`copy_to_clipboard` 动作
   只有在有可复制的选区时才会消费输入。如果没有选区，Gui 会
   表现得如同未设置该键绑定。这对以 `global:` 或 `all:` 为前缀的
   键绑定没有效果。对于键序列，如果动作无法执行，这会重置序列
   （行为与完全没有设置键绑定完全相同）。

   可执行（performable）键绑定不会在应用菜单中显示为菜单快捷键。
   这是因为菜单快捷键会强制动作被执行，而不管终端的状态如何。
   可执行键绑定仍然有效，只是不会作为快捷键标签出现在菜单中。

键绑定触发器并非按前缀组合而唯一。例如，`ctrl+a` 和 `global:ctrl+a`
并不是两个独立的键绑定。后设置的键绑定会覆盖先设置的键绑定。在这种
情况下，会使用 `global:` 键绑定。

可以指定多个前缀。例如，`global:unconsumed:ctrl+a=reload_config` 会
让该键绑定变为全局，并且不消费重新加载配置的输入。

> **Gui**
>
> 格式为 trigger=action；重复的触发器会覆盖较早的一条，空动作会解除绑定，clear 会丢弃所有默认绑定。`gui +list-keybinds` 会打印当前生效的绑定；「键绑定」页面列出了可用的动作和默认值。

## `key-remap`

在 Gui 内重新映射修饰键。这让你可以在应用层面交换或重新分配
修饰键，而不影响系统范围的设置。

格式为 `from=to`，其中 `from` 和 `to` 都是修饰键名称。你可以使用
通用名称，如 `ctrl`、`alt`、`shift`、`super`，
或分侧名称，如 `left_ctrl`、`right_alt` 等。

这不会改变 Gui 之外的键盘布局或按键编码。

示例：

```
key-remap = ctrl=super
key-remap = left_control=right_alt
```

重要说明：

* 这是单向重映射。如果你重映射 `ctrl=super`，那么物理 Ctrl 键会
  充当 Super，但 Super 键仍然是 Super。

* 重映射不具备传递性。如果你重映射 `ctrl=super` 和 `alt=ctrl`，
  按下 Alt 会产生 Ctrl，而不会产生 Super。

* 这同时影响键绑定匹配和终端输入编码。它不会影响键盘布局，也不会
  影响在 Gui 收到按键之前这些键如何被解释。

* 通用修饰键（例如 `ctrl`）会匹配左右两个物理键。使用分侧名称
  （例如 `left_ctrl`）只重映射一侧。

此配置可以重复，以指定多个重映射。

## `window-padding-x`

水平窗口内边距。它在终端单元格与窗口左右边框之间应用内边距。该值以
磅为单位，意味着它会根据屏幕 DPI 适当缩放。

如果该值设置得太大，屏幕将什么也不渲染，因为网格会被内边距完全挤压。
作为用户，你需要自己挑选一个合理的值。如果你选择了不合理的值，日志中
会出现警告。

在运行时更改此配置只会影响新建的终端，即新窗口、标签页等。

要设置不同的左右内边距，请指定两个用逗号分隔的数值。例如
`window-padding-x = 2,4` 会把左边距设为 2、右边距设为 4。如果你想
把两侧内边距设为相同的值，可以使用单个值。例如
`window-padding-x = 2` 会把两侧内边距都设为 2。

## `window-padding-y`

垂直窗口内边距。它在终端单元格与窗口上下边框之间应用内边距。该值以
磅为单位，意味着它会根据屏幕 DPI 适当缩放。

如果该值设置得太大，屏幕将什么也不渲染，因为网格会被内边距完全挤压。
作为用户，你需要自己挑选一个合理的值。如果你选择了不合理的值，日志中
会出现警告。

在运行时更改此配置只会影响新建的终端，即新窗口、标签页等。

要设置不同的上下内边距，请指定两个用逗号分隔的数值。例如
`window-padding-y = 2,4` 会把上边距设为 2、下边距设为 4。如果你想
把两侧内边距设为相同的值，可以使用单个值。例如
`window-padding-y = 2` 会把两侧内边距都设为 2。

## `window-padding-balance`

视口尺寸通常不能被单元格大小整除。在这种情况下，列的末端和最后一行
的底部可能会有一些额外的内边距。如果此项为 `true`，那么这些额外内边距
会自动在四条边之间均衡，以尽量减少某一侧的不均衡。如果此项为
`false`，左上角的网格单元格将始终贴紧边缘，除了其他 `window-padding`
选项可能指定的内边距之外没有额外内边距。

如果设置了其他 `window-padding` 字段并且此项为 `true`，此项仍然会
应用。其他内边距会先应用，并可能影响实际存在多少个网格单元格；而此项
最后应用，以便在给定视口大小和网格单元格大小的情况下均衡内边距。

## `window-inherit-working-directory`

如果为 true，新窗口会继承先前聚焦窗口的工作目录。如果之前没有窗口
处于聚焦状态，则使用默认工作目录（`working-directory` 选项）。

## `tab-inherit-working-directory`

如果为 true，新标签页会继承先前聚焦标签页的工作目录。如果之前没有
标签页处于聚焦状态，则使用默认工作目录（`working-directory` 选项）。

## `split-inherit-working-directory`

如果为 true，新分屏窗格会继承先前聚焦分屏的工作目录。如果之前没有
分屏处于聚焦状态，则使用默认工作目录（`working-directory` 选项）。

## `window-inherit-font-size`

如果为 true，新窗口和标签页会继承先前聚焦窗口的字体大小。如果之前
没有窗口处于聚焦状态，则使用默认字体大小。如果此项为 false，则会
使用配置中 `font-size` 指定的默认字体大小。

## `window-title-font-family`

用于应用窗口和标签页标题的字体。

如果此项未设置，将使用系统默认字体。

<Note>
 可以使用系统上可用的任何字体，此字体不需要是等宽字体。
</Note>

## `window-theme`

用于窗口的主题。有效值：

  * `system` - 使用系统主题。
  * `light` - 无论系统主题如何，都使用浅色主题。
  * `dark` - 无论系统主题如何，都使用深色主题。

> **Gui**
>
> Gui 只接受 system（默认）、light 或 dark。窗口边框是中性表面：它从不采用终端的背景色，终端主题也从不重绘它。

## `window-width`

初始窗口大小。此大小默认以终端网格单元格为单位。两个值都必须设置
才能生效。如果只设置了一个值，它会被忽略。

我们目前不支持以像素为单位指定大小，但未来的更改可以启用这一点。
如果没有指定，应用运行时会决定某个默认大小。

注意，窗口管理器可能会对大小施加限制或覆盖大小。例如，平铺窗口管理器
可能会强制窗口为某个特定大小以适配网格。Gui 对此无能为力，但会
尽力而为。

大于屏幕尺寸的大小会被钳制到屏幕尺寸。这可以用来创建一个默认最大化
的窗口大小。

这不会影响新标签页、分屏或其他嵌套终端元素。它只影响任何新窗口的
初始窗口大小。更改此值不会影响窗口创建之后的大小。它只用于初始大小。

不允许小于 10 列宽、4 行高的窗口。

## `window-position-x`

## `window-position-y`

起始窗口位置。此位置以像素为单位，相对于主显示器的左上角。两个值
都必须设置才能生效。如果只设置了一个值，它会被忽略。

注意，窗口管理器可能会对位置施加限制或覆盖位置。例如，平铺窗口管理器
可能会强制窗口为某个特定位置以适配网格。Gui 对此无能为力，但会
尽力而为。

另请注意，负值也取决于操作系统和窗口管理器。某些窗口管理器可能不允许
把窗口放在屏幕外。

无效位置因运行时而异，但通常位置会被钳制到最接近的有效位置。

## `window-save-state`

是否启用保存和恢复窗口状态。窗口状态包括其位置、大小、标签页、分屏等。
某些窗口状态需要 shell 集成，例如保留工作目录。更多信息请参阅
`shell-integration`。

此配置有两个有效值：

  * `never` 从不保存窗口状态。

  * `always` 每当 Gui 退出时都始终保存窗口状态。

如果你在 Gui 未运行期间把此值改为 `never`，那么下次启动 Gui
不会恢复窗口状态。

如果你在 Gui 未运行期间把此值改为会保存窗口状态的值，那么之前的
窗口状态不会被恢复，因为 Gui 只会在启用此项时于退出时保存状态。

默认值为 `always`。

## `window-new-tab-position`

新标签页创建的位置。有效值：

  * `current` - 在当前聚焦的标签页之后插入新标签页；如果没有聚焦的
    标签页，则插入到末尾。

  * `end` - 把新标签页插入到标签页列表的末尾。

## `window-show-tab-bar`

是否显示标签栏。

有效值：

 - `always` *（默认）*

   始终显示标签栏，即使只有一个标签页。

 - `auto`

   自动显示和隐藏标签栏。只有当存在两个或更多标签页时才会显示
   标签栏。

 - `never`

   从不显示标签栏。标签页只能通过标签页概览或键绑定动作访问。

> **Gui**
>
> Gui 只区分 `never` 与其它值：`auto` 的行为等同于 `always`。

## `focus-follows-mouse`

如果为 true，当存在多个分屏窗格时，鼠标会把焦点移到其所在窗格。
这只适用于当前聚焦的窗口；例如，把鼠标悬停在未聚焦窗口中的分屏上
不会聚焦该分屏并把窗口带到前台。

默认值为 false。

## `clipboard-read`

> **Gui**
>
> allow 或 deny。此版本中 ask 没有阻塞式确认提示，因此行为等同于 deny。

## `clipboard-write`

是否允许终端中运行的程序读/写系统剪贴板（OSC 52，用于在 Google 中
搜索）。读取的默认值是 `ask`，写入的默认值是 `allow`；在此版本中
`ask` 没有阻塞式确认，因此读取实际等同于 `deny`。

有效值：

  * `ask`
  * `allow`
  * `deny`

## `clipboard-trim-trailing-spaces`

去除复制到剪贴板的数据中的尾随空白。这不影响通过 `clipboard-write`
发送到剪贴板的数据。这仅适用于包含其他字符的行的尾随空白。完全空白
的行始终会去除其空白。

## `clipboard-paste-protection`

在粘贴看起来不安全的文本之前要求确认。这有助于防止“复制/粘贴攻击”，
即用户可能因粘贴包含换行符的文本而意外执行不安全命令。

## `clipboard-paste-bracketed-safe`

如果为 true，括起来的粘贴会被视为安全。默认情况下，括起来的粘贴被
视为安全。“括起来的”粘贴是指运行中的程序启用了括起粘贴模式时的粘贴
（该设置由运行中的程序设置，而不是终端模拟器）。

## `title-report`

启用或禁用标题报告（CSI 21 t）。此转义序列允许运行中的程序查询终端
标题。这是一个常见的安全问题，默认禁用。

<Warning>
 这充其量会暴露敏感信息，最坏情况下（配合恶意构造的标题和少量用户
交互）可以启用任意代码执行。
</Warning>

## `image-storage-limit`

每个终端屏幕可用于图像数据（例如 Kitty 图像协议）的总字节数。最大值
为 4,294,967,295（4GiB）。默认值为 320MB。如果设为 0，则所有图像协议
都会被禁用。

此值为主屏幕和备用屏幕分别计算，因此每个表面的实际限制是这个值的
两倍。

## `copy-on-select`

是否自动把选中的文本复制到剪贴板。`true` 会优先复制到选区剪贴板，
否则会复制到系统剪贴板。

值 `clipboard` 会始终把文本同时复制到选区剪贴板和系统剪贴板。

中键粘贴会始终使用选区剪贴板。即使此项为 `false`，中键粘贴也始终
启用。

默认值为 false。

> **Gui**
>
> none、primary、clipboard 或 both。Windows 没有选区剪贴板，因此 primary 不产生任何效果，both 只复制到系统剪贴板。

## `right-click-action`

用户右键单击终端表面时要执行的动作。

有效值：
  * `context-menu` - 显示上下文菜单。
  * `paste` - 粘贴剪贴板的内容。
  * `copy` - 把选中的文本复制到剪贴板。
  * `copy-or-paste` - 如果有选区，把选中的文本复制到剪贴板；
     否则，粘贴剪贴板的内容。
  * `ignore` - 什么也不做，忽略右键单击。

默认值为 `context-menu`。

## `click-repeat-interval`

把一次点击视为重复点击（双击、三击等）或一次全新的单击之间的时间
间隔，单位为毫秒。值为 0 会使用平台特定的默认值，Windows 上为 500ms。

## `config-file`

要读取的附加配置文件。此配置可以重复，以读取多个配置文件。配置文件
本身也可以加载更多配置文件。路径相对于包含 `config-file` 指令的文件。
对于命令行参数，路径相对于当前工作目录。

在文件路径前加上 ? 字符可以抑制文件不存在时的错误。如果你想包含一个
以字面量 ? 字符开头的文件，请把文件路径用双引号（"）括起来。

不允许循环。如果检测到循环，会记录一条错误，并忽略该配置文件。

配置文件会在定义它们的配置之后、按照定义顺序加载。**这是一个非常
微妙但重要的要点。** 换句话说：配置文件要等到整个配置加载完毕后才会
生效。例如，在下面的配置中：

```
config-file = "foo"
a = 1
```

如果 "foo" 包含 `a = 2`，那么 `a` 的最终值将是 2，因为 `foo` 是在
配置了嵌套 `config-file` 值的配置文件之后加载的。

## `config-default-files`

为 true 时加载默认配置文件，即 `%APPDATA%\gui\config`（通常是 `C:\Users\<你>\AppData\Roaming\gui\config`）。

为 false 时不加载默认配置文件，只读取命令行 `--config-file` 给出的文件。

这是仅限命令行的配置。写在配置文件里不会生效：Gui 会把它当作未知选项给出警告并忽略。它只能通过命令行参数设置。

## `confirm-close-surface`

在关闭表面之前确认是否应关闭该表面。

此项默认为 `true`。如果设为 `false`，表面会在没有任何确认的情况下
关闭。也可以把它设为 `always`，这会始终确认关闭表面，即使 shell
集成表示没有进程正在运行。

## `quick-terminal-position`

“快速”终端窗口的位置。要了解更多关于快速终端的信息，请参阅
`toggle_quick_terminal` 绑定动作的文档。

有效值：

  * `top` - 终端出现在屏幕顶部。
  * `bottom` - 终端出现在屏幕底部。
  * `left` - 终端出现在屏幕左侧。
  * `right` - 终端出现在屏幕右侧。
  * `center` - 终端出现在屏幕中央。

每次唤出快速终端时都会重新读取配置，因此在文件里改完位置后无需重启，下次显示即生效。

<Note>
 没有用于切换快速终端的默认键绑定。要启用此功能，请把
`toggle_quick_terminal` 动作绑定到一个按键。
</Note>

## `quick-terminal-size`

快速终端的大小。

大小可以按屏幕尺寸（高度/宽度）的百分比指定，也可以按像素指定绝对
大小。百分比值带有 `%` 后缀（例如 `20%`），像素值带有 `px` 后缀
（例如 `300px`）。不带后缀的裸值会被忽略，沿用默认大小。

只指定一个大小时，该大小参数会影响快速终端在其*主轴*上的大小，
具体取决于其位置：位于顶部或底部的快速终端使用高度，位于左侧或右侧
的使用宽度。居中的快速终端的主轴取决于显示器的方向：横屏显示器上为
高度，竖屏显示器上为宽度。

对于非居中位置的快速终端，除非指定了另一个大小参数（与第一个参数用
逗号 `,` 分隔），否则*次轴*会被最大化。百分比和像素大小可以混用：
例如，对于位于顶部的快速终端，大小 `50%,500px` 表示高度为半屏、
宽度为 500 像素。

未指定大小时，默认厚度为 400 DIP（按显示器 DPI 缩放）：顶部/底部占满宽度，
左侧/右侧占满高度；居中的快速终端在横屏显示器上默认 800×400 DIP，竖屏上为
400×800 DIP。

## `quick-terminal-screen`

快速终端应显示在哪个屏幕上。

有效值：

 * `main` - 操作系统推荐的主屏幕（`DisplayArea.Primary`）。此屏幕由操作系统定义，而不是由 Gui 选择。

 * `mouse` - 鼠标当前悬停所在的屏幕。

默认值为 `mouse`。其它值（包括 Ghostty 的 `macos-menu-bar`）都按 `mouse` 处理。

## `quick-terminal-animation-duration`

快速终端进入和退出动画的时长（以秒为单位），默认为 0.2。把它设为 0
可完全禁用动画。配置在每次显示时重新读取，因此可以在运行时更改。

## `quick-terminal-autohide`

当焦点转移到其他窗口时自动隐藏快速终端。默认为 `true`。把它设为
`false` 可以让快速终端在失去焦点时仍保持打开。

## `shell-integration`

是否启用 shell 集成自动注入。shell 集成通过启用一系列功能大幅提升
终端体验：

  * 工作目录报告，使新标签页、分屏能继承先前终端的工作目录。

  * 提示符标记，从而启用 "jump_to_prompt" 键绑定。

  * 如果你正停留在提示符处，关闭终端将不会要求确认。

  * 使用复杂提示符调整窗口大小时，绘制效果通常要好得多。

允许的值：

  * `none` - 不做任何自动注入。你仍然可以手动配置 shell 来启用
    集成。

  * `detect` - 根据文件名检测 shell。

  * `bash`、`elvish`、`fish`、`nushell`、`zsh` - 使用该特定的 shell
    注入方案。

默认值为 `detect`。

> **Gui**
>
> 在 Windows 上只会向 PowerShell 和 bash 注入；其他 shell 会收到一条提示，不做处理。

## `shell-integration-features`

要启用的 shell 集成特性。这些需要已加载我们的 shell 集成，可以通过
shell-integration 自动加载，也可以手动加载。

其格式是用逗号分隔的待启用特性列表。如果给某个特性加上 `no-` 前缀，
则禁用该特性。如果省略某个特性，则使用其默认值。你也可以使用 `true`
或 `false` 打开或关闭所有特性。

示例：`cursor`、`no-cursor`、`title`、`no-title`

可用特性：

  * `cursor` - 在提示符处把光标设为条形（默认启用）。加上 `:steady`
    可要求不闪烁的稳定条形，例如 `cursor:steady`。

  * `title` - 通过 shell 集成设置窗口标题（默认启用）。

  * `sudo`、`ssh-env`、`ssh-terminfo`、`path` - 为兼容 Ghostty 配置而
    接受，但在 Windows 上没有效果。Gui 无论是否设置 `path`，都会把
    自己的 CLI 目录（包含 `gui.exe` 的 `bin`）加入每个 shell 的 PATH。

## `osc-color-report-format`

设置请求颜色信息的 OSC 序列的报告格式。Gui 目前支持 OSC 10
（前景色）、OSC 11（背景色）和 OSC 4（256 色调色板）查询，默认情况下
报告的值是放大后的 RGB 值，每个分量为 16 位。大多数终端都是这样报告
这些值的。不过，某些传统应用可能需要 8 位、未放大的分量。我们也支持
完全关闭报告。各分量为小写十六进制值。

允许的值：

  * `none` - OSC 4/10/11 查询不收到任何回复

  * `8-bit` - 颜色分量以未放大形式返回，例如 `rr/gg/bb`

  * `16-bit` - 颜色分量以放大形式返回，例如 `rrrr/gggg/bbbb`

默认值为 `16-bit`。

## `vt-kam-allowed`

如果为 true，允许在终端内使用“KAM”模式（ANSI 模式 2）。KAM 会在应用
请求时禁用键盘输入。这不是常见特性，不建议启用。此处不再进一步说明，
因为如果你知道自己需要 KAM，你就是知道。如果你不确定自己是否需要
KAM，那你就不需要它。

## `custom-shader`

在默认着色器之后运行的自定义着色器。这是所有平台通用的 GLSL 语法
着色器的文件路径。

<Warning>
 无效的着色器可能导致 Gui 无法使用，例如让窗口完全变黑。如果发生
这种情况，你可以取消设置此配置以禁用该着色器。
</Warning>

自定义着色器支持基于 Shadertoy 着色器并与之兼容。着色器应指定一个
`mainImage` 函数，可用的 uniform 大体上与 Shadertoy 一致，但有一些
注意事项和 Gui 特有的扩展。

可供着色器使用的 uniform 值如下：

 * `sampler2D iChannel0` - 输入纹理。

   包含当前终端屏幕的纹理。如果指定了多个自定义着色器，前一个着色器
   的输出会被写入该纹理，以便组合多个效果。

 * `vec3 iResolution` - 输出纹理大小，`[width, height, 1]`（单位为像素）。

 * `float iTime` - 自第一帧渲染以来的时间，以秒为单位。

 * `float iTimeDelta` - 自上一帧渲染以来的时间，以秒为单位。

 * `float iFrameRate` - 平均帧率。（目前不支持）

 * `int iFrame` - 截至目前已渲染的帧数。

 * `float iChannelTime[4]` - 视频或声音输入的当前时间。（不适用）

 * `vec3 iChannelResolution[4]` - 4 个输入采样器的分辨率。

   目前只存在 `iChannel0`，且 `iChannelResolution[0]` 与 `iResolution`
   相同。

 * `vec4 iMouse` - 鼠标输入信息。（目前不支持）

 * `vec4 iDate` - 日期/时间信息。（目前不支持）

 * `float iSampleRate` - 音频采样率。（不适用）

Gui 特有的扩展：

 * `vec4 iCurrentCursor` - 关于终端光标的信息。

   - `iCurrentCursor.xy` 是当前光标的 -X、+Y 角。
   - `iCurrentCursor.zw` 是当前光标的宽度和高度。

 * `vec4 iPreviousCursor` - 关于上一个终端光标的信息。

 * `vec4 iCurrentCursorColor` - 终端光标的颜色。

 * `vec4 iPreviousCursorColor` - 上一个终端光标的颜色。

 * `vec4 iCurrentCursorStyle` - 终端光标的样式

   为各种光标样式定义了用于简化使用的宏：

   - `CURSORSTYLE_BLOCK` 或 `0`
   - `CURSORSTYLE_BLOCK_HOLLOW` 或 `1`
   - `CURSORSTYLE_BAR` 或 `2`
   - `CURSORSTYLE_UNDERLINE` 或 `3`
   - `CURSORSTYLE_LOCK` 或 `4`

 * `vec4 iPreviousCursorStyle` - 上一个终端光标的样式

 * `vec4 iCursorVisible` - 终端光标的可见性。

 * `float iTimeCursorChange` - 终端光标发生变化的时间戳。

   当终端光标改变位置或颜色时，它会被设为与 `iTime` uniform 相同的值，
   让你可以用 `iTime` 减去它来计算自变化以来经过的时间。

 * `float iTimeFocus` - 表面最近一次获得焦点的时间戳。

   当表面获得焦点时，它会被设为 `iTime` 的当前值，工作方式与
   `iTimeCursorChange` 类似。这让你可以通过计算 `iTime - iTimeFocus`
   来得到获得或失去焦点以来经过的时间。可用它创建在终端重新获得焦点时
   重新开始的动画。

 * `int iFocus` - 表面的当前聚焦状态。

   表面聚焦时设为 1.0，未聚焦时设为 0.0。这使着色器能够检测未聚焦
   状态，并避免因不频繁的“欺骗性帧”（例如修饰键按下、未聚焦分屏窗格
   中的链接悬停事件）导致的大时间差而产生动画伪影。检查
   `iFocus > 0` 以确定表面当前是否聚焦。

 * `vec3 iPalette[256]` - 256 色终端调色板。

   终端调色板中全部 256 种颜色的 RGB 值，归一化到 [0.0, 1.0]。索引
   0-15 是 ANSI 颜色，16-231 是 6x6x6 色立方，232-255 是灰度颜色。

 * `vec3 iBackgroundColor` - 终端背景色（RGB）。

 * `vec3 iForegroundColor` - 终端前景色（RGB）。

 * `vec3 iCursorColor` - 终端光标颜色（RGB）。

 * `vec3 iCursorText` - 终端光标文本颜色（RGB）。

 * `vec3 iSelectionBackgroundColor` - 选区背景色（RGB）。

 * `vec3 iSelectionForegroundColor` - 选区前景色（RGB）。

如果着色器编译失败，该着色器会被忽略。任何与着色器编译相关的错误都
不会显示为配置错误，只会出现在日志中，因为着色器编译发生在配置加载
之后的专用渲染线程上。交互式开发请使用
[shadertoy.com](https://shadertoy.com)。

此配置可以重复多次以加载多个着色器。着色器会按照指定的顺序运行。

此配置可以在运行时更改，并会影响所有已打开的终端。

## `custom-shader-animation`

如果为 `true`（默认），在使用自定义着色器时，聚焦的终端表面会运行
动画循环。这会略微增加 CPU 占用（通常低于 10%），但允许着色器播放
动画。只有当存在自定义着色器且终端处于聚焦状态时才会运行。

如果设为 `false`，终端和自定义着色器只会在终端更新时渲染。这样更
高效，但着色器不会播放动画。

也可以把它设为 `always`，这会无论终端是否聚焦都始终运行动画循环。
动画循环仍只在使用自定义着色器时运行。注意，这会为每个终端表面消耗
更多 CPU，根据着色器和你的终端使用情况，开销可能相当大。

此配置可以在运行时更改，并会影响所有已打开的终端。

## `bell-features`

如果你的运行时支持响铃，要启用的响铃特性。并非所有特性在所有运行时
上都可用。其格式是用逗号分隔的待启用特性列表。如果给某个特性加上
`no-` 前缀，则禁用该特性。如果省略某个特性，则使用其默认值。

有效值：

 * `system`

   指示系统使用内置系统功能通知用户。这可能产生视听效果、通知，或
   完全不同的其他效果。

 * `audio`

   播放自定义声音。

 * `attention` *（默认启用）*

   当 Gui 未聚焦时请求用户注意，直到它再次获得焦点。

 * `title` *（默认启用）*

   在被提醒的表面的标题前加上一个铃铛 emoji（🔔），直到终端重新
   获得焦点或发生交互（例如键盘输入）。

 * `border`

   在被提醒的表面周围显示边框，直到终端重新获得焦点或发生交互
   （例如键盘输入）。

示例：`audio`、`no-audio`、`system`、`no-system`

## `bell-audio-path`

如果 `audio` 是已启用的响铃特性，这是音频文件的路径。如果路径不是
绝对路径，则视为相对于引用它的配置文件所在目录，或如果它是作为 CLI
标志使用的，则相对于当前工作目录。路径可以加上 `~/` 前缀以引用用户的
主目录。

## `bell-audio-volume`

如果 `audio` 是已启用的响铃特性，这是播放音频文件的音量（相对于系统
音量）。这是一个浮点数，范围从 0.0（静音）到 1.0（尽可能响）。默认
值为 0.5。

## `desktop-notifications`

如果为 `true`（默认），终端中运行的应用可以使用 OSC 9 或 OSC 777 等
某些转义序列显示桌面通知。

## `notify-on-program-status`

窗格处于后台时，哪些 OSC 7501 程序状态上报会触发桌面通知。取值为逗号
分隔的列表，每项都可以加 `no-` 前缀取反：

 * `block` — 程序正在等待用户操作（批准、回答问题、提供凭据）。
 * `done` — 程序完成了一项工作。
 * `fail` — 程序失败并停止。

三项默认全部开启。例如 `no-done` 会保留等待操作和失败的通知，但不再
通知已完成的工作。

## `progress-style`

如果为 `true`（默认），终端中运行的应用可以使用 ConEmu OSC 9;4 转义
序列显示图形进度条。如果为 `false`，进度条序列会被静默忽略。

## `bold-color`

修改终端中粗体文本使用的颜色。

可以把此项设为一个特定颜色，格式与 `background` 或 `foreground` 相同
（例如 `#RRGGBB`，也支持其他格式；请参阅前述文档）。如果设置了特定
颜色，该颜色将始终用于默认的粗体文本颜色。它会将其余粗体颜色设为
`bright`。

也可以把此项设为 `bright`，这会为粗体文本使用亮色调色板。例如，如果
文本是红色，那么粗体会使用亮红色。终端调色板通过 `palette` 设置，
但也可以被终端应用本身通过 OSC 4 等转义序列覆盖。（先前的配置
`bold-is-bright` 已被废弃，并由这种用法取代）。

## `faint-opacity`

淡色文本的不透明度（透明度的反面）。值为 1 表示完全不透明，值为 0
表示完全透明。小于 0 或大于 1 的值会被钳制到最接近的有效值。

## `term`

这用于设置 `TERM` 环境变量。

## `auto-update`

`check`（默认）会在启动时于后台检查 GitHub 上是否有更新的版本，最多每 24 小时
一次，发现新版本时显示提示气泡。`off` 关闭这一启动检查；命令面板中的
“检查更新”仍然可用。

## `auto-update-channel`

`stable`（默认）只读取最新的正式版本；`tip` 也会包含预发布版本。
