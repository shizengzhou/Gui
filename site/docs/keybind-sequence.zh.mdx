---
title: 触发序列
description: 需要连续多次按键才能触发的按键绑定。
---

Gui 支持需要一串触发器才能激活动作的按键绑定。例如先按 `ctrl+a`，再按 `n`，才打开新窗口。在其它软件里，这有时被称为 “leader key”、“key chord” 或 “key table” 等等。

要指定一串触发器，请使用[常规触发器语法](/docs/config/keybind#trigger)，并在序列中的各个触发器之间用 `>` 字符分隔。示例如下：

```ini
keybind = ctrl+a>n=new_window
```

<Warning>
如果把序列作为命令行参数传给 `gui`，由于 `>` 在大多数 shell 中是特殊字符，你多半需要给按键绑定加引号。例如：`gui --keybind='ctrl+a>n=new_window'`
</Warning>

触发序列有一些特殊的处理规则：

- Gui 会无限期地等待序列中的下一个键，没有超时。用于构成前缀的按键会被暂存，不会发送给程序。

- 如果一个按键既是普通绑定、又是某条序列的开头，序列优先：按下 `ctrl+a` 只会等待，不会执行普通绑定，命令面板也不再为该动作显示这个快捷键。

- 如果下一个键接不上序列，暂存的前缀会重新发送给程序，新按下的键则按正常流程处理。因此先按 `ctrl+a` 再按 `x`，会送出 `^A` 和 `x`，效果和没有序列时一样。

- 如果此前绑定的序列前缀被用在一条新的非序列绑定中，那么先前整条序列都会被解绑。例如先绑定 `ctrl+a>n` 和 `ctrl+a>t`，再直接绑定 `ctrl+a`，那么 `ctrl+a>n` 和 `ctrl+a>t` 都会变为未绑定。

- 空动作只解绑对应的那条序列，例如 `keybind = ctrl+a>n=`，不影响共用同一前缀的其它序列。

- 带 `global:` 前缀的触发器不允许使用序列；这样的行会被拒绝，并在日志里留下警告。

- 加 `unconsumed:` 时，动作照常执行，随后暂存的前缀按键和完成序列的那个键都会发送给程序。

- 加 `performable:` 时，如果序列最后的动作无法执行，序列会被重置而不是触发：暂存的按键重放给程序，新按键也照常送入。

序列长度没有限制，最后一步可以接[动作参考](/docs/config/keybind/reference)里的任何动作。命令面板与提示中按键按顺序用空格分隔显示（`Ctrl+A N`），配置文件里则用 `>` 书写。
